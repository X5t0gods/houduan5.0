## 1 产品概述

### 1.1 产品定位

> **一句话定位**：为社区超市提供"比 Excel 强、比 ERP 轻"的一体化经营管理系统。

社区超市（100～500㎡，3～15 名员工，1～2 台收银机）是零售业态中数量最多的经营主体。
它们的管理需求真实存在，却处于供给空档：

- 传统商超 ERP 功能庞大、按年收费、需要实施，投入产出比极低；
- Excel 手工记账易错、无协同、数据无法沉淀；
- 现有 SaaS 收银软件数据在第三方、断网不可用、难以定制。

本产品填补的正是这个空档：**轻量部署、开箱即用、数据自主、且具备数据洞察能力**。

### 1.3 核心价值主张

| 价值 | 解决什么问题 | 对应功能 |
| --- | --- | --- |
| **收银快** | 高峰期排队、收银员手忙脚乱 | 全屏收银台、快捷键全流程、扫码回车即加购、常用商品快捷区、挂单 |
| **账目清** | 库存对不上、不知道货去哪了 | 流水驱动库存、库存可追溯、盘点冻结快照、进销存勾稽校验 |
| **决策有据** | 进货靠拍脑袋、不知什么好卖 | 经营看板、报表体系、**购物篮关联分析**、智能补货建议 |
| **不亏钱** | 促销算错价、重复扣款、储值套利 | 促销价格试算、结算幂等、储值本金/赠送双轨 |
| **上手快** | 人员流动大、培训成本高 | 极简交互、快捷键、必填校验前置、异常标红 |

### 1.4 产品边界

**做什么**

- 门店日常经营：收银、会员、促销、交班
- 进销存：商品、采购、库存（含盘点/报损/调拨）
- 数据分析：经营看板、报表、购物篮关联分析、预测与补货
- 系统管理：用户、角色权限、参数、日志、备份

**不做什么（一期）**

| 不做 | 原因 |
| --- | --- |
| 移动 App / 小程序 | 门店场景以 PC 收银为主 |
| 热敏打印机驱动对接 | 走浏览器打印，零硬件依赖 |
| 线上商城 / 到家配送 | 偏离"门店管理"核心 |
| 多仓 / 中央仓 | 社区超市无中心仓需求 |
| 财务会计凭证 | 只做业务账（应收应付） |
| 人脸识别 / 自助收银 | 成本与场景不匹配 |

## 2 用户场景与用户故事

### 2.1 核心场景

#### 场景一：早高峰收银（每日 07:00-09:00）

> 王姐的店早上最忙。收银员小李刚上岗第三天，前面排了 5 个人。
>
> **小李**：扫码枪一扫，商品直接进购物车；遇到称重的蔬菜，直接输重量；
> 常来的张阿姨报了手机号后 4 位，系统认出会员，自动用会员价；
> 满 50 元自动减 5 元，屏幕上有提示；刷卡收款，找零自动算好；
> 小票打印，全程没用鼠标。

**产品要求**：全流程键盘可操作；促销优惠**即时可见**；会员识别**≤3 秒**。

#### 场景二：顾客临时离场

> 一位顾客扫了几件商品后想起还有东西没拿，说"等我一下"。
>
> **小李**：按 F5 挂单，先给后面的顾客结账；顾客回来后从挂单列表取出，购物车原样恢复。

**产品要求**：挂单必须**完整保存购物车**（含数量、改价、会员），取单后状态一致。

#### 场景三：月末盘点（不停业）

> 老陈要盘生鲜区，但店还得照常营业。
>
> **老陈**：发起"按分类盘点"，系统**冻结当时的账面数**；
> 花了 1 小时清点，期间卖出去 20 多件商品；
> 录入实盘数，系统按"实盘 − 冻结账面"算差异；
> 差异项必须填原因（破损/漏记/串码），提交给店长审核。

**产品要求**：盘点期间的正常销售**不能被算成盘亏**。

#### 场景四：临期商品处理

> 老陈每天看一次临期预警。
>
> **老陈**：系统列出 3 天内到期的商品与数量；对确实卖不掉的做报损登记，填原因；
> 对还能卖的做降价促销。

**产品要求**：临期预警按保质期阈值（默认 30 天）自动计算，剩余天数按天展示。

#### 场景五：王姐看经营情况（晚上打烊后）

> 王姐想知道今天赚了多少、什么卖得好、明天该进什么货。
>
> **王姐**：打开看板 — 今日销售额、客单价、毛利率、新增会员一目了然；30 天趋势看走势；
> 打开"智能分析"— 系统告诉她"买青岛啤酒的顾客 62.4% 也买了花生米"，
> 她一键把这条建议变成"啤酒+花生米组合装"促销。

**产品要求**：看板**打开即用**（无需配置）；分析结论要有**业务解读**，不能只给数字。

#### 场景六：促销效果复盘

> 促销做了一周，王姐想知道值不值。
>
> **王姐**：打开促销效果分析 — 触发 486 单、优惠支出 3248 元、
> 有促销 vs 无促销的销售额对比曲线。

**产品要求**：促销效果需提供**对比维度**（有促销 vs 无促销），而不只是绝对数。

## 4 功能需求

> **优先级说明**：P0 不做则系统不可用；P1 影响核心体验；P2 提升竞争力。
> 每个模块列出：功能点、优先级、验收要点。

### 4.1 认证与权限（AUTH）

| 功能点 | 优先级 | 验收要点 |
| --- | --- | --- |
| 账号密码登录 | P0 | 图形验证码校验；失败达阈值锁定账号；登录日志留痕 |
| 退出登录 | P0 | 清除本地令牌；服务端可作废 |
| 令牌刷新 | P1 | access_token 过期用 refresh_token 换取，用户无感知 |
| 当前用户信息 | P0 | 返回权限码数组，前端据此生成菜单 |
| 修改本人密码 | P1 | 需校验原密码；新密码强度校验 |
| 用户管理 | P0 | 增删改查、重置密码、启用停用 |
| 角色管理 | P0 | 角色增删改；配置数据范围 |
| 权限配置 | P0 | **勾选式权限树**；保存后该角色用户下次登录生效 |
| 操作日志 | P1 | 记录变更前后值；可按模块/时间检索 |
| 登录日志 | P1 | 记录结果与失败原因；可按账号检索 |

**权限模型**：三级控制。

| 级别 | 实现 |
| --- | --- |
| 菜单级 | 按权限码过滤路由表，无权限不注册 |
| 按钮级 | `v-permission` 指令，无权限移除 DOM + 后端接口校验 |
| 数据级 | 按角色 `data_scope` 过滤（ALL / STORE / DEPT / SELF） |

**关键特性：一人多岗**。社区超市常见"收银员兼理货"，一个用户可绑定多个角色，权限取并集。

### 4.2 基础数据（BASE）

| 功能点 | 优先级 | 验收要点 |
| --- | --- | --- |
| 门店管理 | P0 | 支持多门店；门店编码唯一 |
| 收银台管理 | P0 | 每台机器绑定一个收银台，用于交班与数据归属 |
| 计量单位 | P0 | 支持基本单位与辅助单位（如 1 箱 = 12 瓶） |
| 货架/库位 | P1 | 商品可绑定默认陈列货架 |
| 数据字典 | P1 | 支付方式、流水类型等枚举可视化管理 |

### 4.3 商品管理（PRD）

| 功能点 | 优先级 | 验收要点 |
| --- | --- | --- |
| 商品列表 | P0 | 支持按名称/编码/条码检索；展示库存与状态 |
| 商品建档 | P0 | 编码与条码唯一校验；售价低于进价时二次确认 |
| 商品修改 | P0 | 价格变更需写价格历史并记操作日志 |
| 停用/启用 | P0 | **只停用不删除**；停用后收银台扫码提示"商品已停用" |
| 商品删除 | P1 | 仅无任何业务流水时允许 |
| 三级分类 | P0 | 树形结构；**被商品引用的分类只能停用不能删除** |
| 一品多码 | P1 | 一个商品可绑定多个条码（含整箱码） |
| Excel 导入 | P1 | 逐行校验并返回失败报告（含行号与原因），允许部分成功 |
| 称重商品 | P0 | 数量可输小数；单位绑定 |
| 保质期商品 | P0 | 必须填保质期天数；收货时录入批次与到期日 |

### 4.4 供应商与采购（PUR）

| 功能点 | 优先级 | 验收要点 |
| --- | --- | --- |
| 供应商档案 | P0 | 支持现结/账期；只停用不删除；停用后不能下单 |
| 采购订单列表 | P0 | 按状态筛选（草稿/已审核/部分收货/已完成/已作废） |
| 采购建单 | P0 | 明细支持批量选择商品；可由补货建议一键带入 |

| 收货入库 | P0 | 支持部分收货；**超收校验**；保质期商品必录批次 |

### 4.5 库存管理（INV）

| 功能点 | 优先级 | 验收要点 |
| --- | --- | --- |

| 库存流水 | P0 | 每次变动记录**变动前后数量**与来源单据 |
| 三类预警 | P0 | 缺货（≤安全库存）、积压（>上限）、临期（≤阈值天数） |

**核心设计**：库存采用「流水驱动」——`inv_stock_flow` 是唯一真相源，库存表只是冗余快照。
保证任意时点库存可独立复算，且每笔变动可追溯到来源单据。


**交互要点**

| 要点 | 设计 |
| --- | --- |
| 扫码即加购 | 输入框回车即加入；成功后自动清空并保持焦点 |
| 同商品累加 | 相同商品且未改价时累加数量（称重商品不累加） |
| 促销可见 | 优惠明细逐条展示（如"满 50 减 5"），让收银员能向顾客解释 |
| 会员优先 | 识别会员后自动取会员价，并叠加会员专享促销 |
| 错误友好 | 商品不存在/库存不足/余额不足，给出明确中文提示，不打断流程 |
| 键盘优先 | 全流程无需鼠标，符合收银员操作习惯 |

### 5.2 列表页统一规范

所有列表页复用同一套结构（`ListPage` 组件），保证一致性：

| 区域 | 内容 |
| --- | --- |

| 分页 | 总数 + 每页条数（10/20/50/100）+ 跳页 |

**空状态**：给出引导文案（如"暂无商品，请先新建或导入"），而不是空白。

## 7 非功能需求

| 类别 | 要求 |
| --- | --- |
| **性能** | 条码解析 P95 ≤ 200ms；结算 P95 ≤ 500ms；看板打开 ≤ 2s；支持 5 台收银机并发 |

| **部署** | 单机可部署；不依赖 Redis / 消息队列等外部中间件 |

### 9.3 状态机

**销售单**：`FINISHED`（已完成）→ `RETURNED`（已退货）/ `VOID`（已作废）

**采购单**：`DRAFT`（草稿）→ `AUDITED`（已审核）→ `PARTIAL`（部分收货）→ `FINISHED`（已完成）；任一阶段可 `VOID`（作废）

**盘点单**：`DRAFT`（盘点中）→ `SUBMITTED`（待审核）→ `AUDITED`（已审核）/ `VOID`（已作废）

**报损单**：`DRAFT`（草稿）→ `SUBMITTED`（已提交）→ `AUDITED`（已审核）

**促销活动**：`DRAFT`（未开始）→ `RUNNING`（进行中）→ `STOPPED`（已停用）/ `EXPIRED`（已结束）

**收银班次**：`OPEN`（进行中）→ `CLOSED`（已交班）→ `AUDITED`（已审核）

**会员状态**：`1` 正常 / `0` 冻结 / `2` 挂失
